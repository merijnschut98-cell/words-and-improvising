# v16 Flair implementation plan

Spec: `docs/superpowers/specs/2026-11-11-v16-flair-design.md`. Read it first; this plan does not repeat the rules.

**Method.** TDD per task: write the named test(s), run `npm test` and see them fail, write the smallest code that passes, run `npm test` (all green), commit. One commit per task. Pure logic first (core), then storage and sync, then UI, then e2e and the service worker. Small tasks; each names its files and tests.

**Before starting.**

- Merijn's answers to the spec's open questions change names and a few numbers only (Q2 title names, Q3 check name, Q6 stub, Q7 backfill, Q8 silver share, Q9 default goal, Q10 sound default). Keep them as constants at the top of `src/core/flair.js` and in i18n so an answer is a one-line change.
- **Dependency:** the "levels appear after the previous level is finished" change (another agent) must be merged before Task 14 (path map). Tasks 1–13 do not depend on it. If it is not merged when Task 14 starts, stop and ask; do not re-implement gating.
- Other v16 work touching the same files: quiz length 5–8 (`course.js`, content) and "continue where you left off" (`nextLesson`). Rebase on them before Task 6 and Task 14; the rules here do not depend on the question count (silver is a share of levels, the module check has its own count).
